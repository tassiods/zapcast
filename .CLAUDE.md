## Purpose

ZapCast: WhatsApp bulk-messaging web app. Go backend + embedded single-page frontend. Uses `whatsmeow` for WhatsApp Multi-Device. SQLite for persistence.

## Stack

- Go 1.26 (`go.mod`)
- `go.mau.fi/whatsmeow` — WhatsApp client (unofficial, MD protocol)
- `github.com/mattn/go-sqlite3` — SQLite driver (cgo)
- `google.golang.org/protobuf` — whatsmeow protobuf
- `log/slog` — structured logging (stdlib)
- Frontend: plain HTML/CSS/JS in `internal/server/web/`, embedded via `go:embed`; Vite bundle (`web/dist/`) served under `-tags prod`

## Run

Dev:
```bash
go mod download
go run .
```
Defaults: `http://127.0.0.1:3000`. SQLite/session dbs written to `./store/`.

Docker:
```bash
docker-compose up -d
docker-compose logs -f
```

Env vars:
- `HOST` (default `127.0.0.1`)
- `PORT` (default `3000`)
- `STORE_DIR` (default `store`)
- `LOG_LEVEL` (`debug`|`info`|`warn`|`error`, default `info`)
- `LOG_FORMAT` (`text`|`json`, default `text`)
- `AUTH_TOKEN` (opt-in bearer token; required for non-loopback `HOST`)
- `FRONTEND_ORIGIN` (CORS allowlist; pin when serving SPA from a different origin)
- `BROADCAST_DELAY_MS` (default `500`, clamped 100–30000)
- `BROADCAST_DELAY_JITTER` (default `0.3`, fraction 0–0.9)
- `BROADCAST_HOURLY_CAP` (default `0` = unbounded)

## Test

```bash
go test ./...

```

Backend tests live in `internal/server/*_test.go` (unit + integration + smoke). Helper `newTestStore(t)` returns temp SQLite-backed `ContactStore`. Coverage floor 65% enforced in CI.

Frontend: `npm test` (Vitest), `npm run test:types` (tsc), `npm run test:e2e` (Playwright).

## Architecture

Repo root holds only `main.go` (thin entry → `server.Run()`), `cmd/seed/` and config files. All server code lives in `internal/server/` so external imports of `App` are impossible.

- `main.go` — calls `server.Run()`.
- `internal/server/server.go` — `App` struct, `Run()`, lifecycle, route table, middleware chain, graceful shutdown (`shutdownCtx`).
- `internal/server/handlers_*.go` — REST handlers, all named `handle*` or area-specific (`listContacts`, `createGroup`, …).
- `internal/server/broadcast.go` + `broadcaster.go` — `/api/broadcast` handler, `StartHandle` (mutex/cancel/WG), worker loop.
- `internal/server/outbox.go` — retry worker for transient send failures.
- `internal/server/contacts.go` — `ContactStore`: ctx-aware CRUD, broadcasts, message state, receipts.
- `internal/server/migrations.go` + `migrations/NNNN_*.sql` — versioned schema migrations, tracked in `schema_migrations` table.
- `internal/server/errors.go` — `LocalizedError` interface, `APIError` envelope.
- `internal/server/i18n*.go` — translation tables (en/pt/es) + ETag cache.
- `internal/server/sse.go` + `sse_events.go` — typed SSE hub.
- `internal/server/auth.go` — `/api/status`, QR pairing, logout, `Version()`.
- `internal/server/wa_events.go` — whatsmeow → app bridge (shutdown-aware ctx).
- `internal/server/ratelimit.go` — per-IP token bucket.
- `internal/server/waclient.go` — whatsmeow adapter interface (testable via `fakeWA`).
- `internal/server/web/` — SPA source + Vite `dist/`; `embed_dev.go` / `embed_prod.go` pick subtree per build tag.
- `store/` — gitignored runtime dir: `device.db` (whatsmeow session), `zapcast.db` (app data).
- `Dockerfile` — multi-stage build (golang:1.26-alpine → alpine runtime, non-root).
- `docker-compose.yml` — exposes 3000, mounts `/app/store`.

## Data

SQLite, WAL mode, FK enabled, tuned pragmas embedded in DSN (`internal/server/contacts.go:80-93`). `SetMaxOpenConns(1)` serialises writes.

Tables: `contacts` (phone PK), `contact_groups`, `group_members`, `template_vars`, `broadcasts`, `broadcast_messages`, `outbox`, `schema_migrations`.

## Key routes

- `GET /healthz` / `GET /readyz` — probes (no auth)
- `GET /api/auth/required` — does the backend require a bearer token?
- `GET /api/status` — connection state
- `POST /api/auth/qr` — QR login stream
- `POST /api/auth/login` / `POST /api/auth/logout` / `POST /api/auth/session/logout`
- `GET|POST|PUT|DELETE /api/contacts` (search: `?q=`, paging: `?page=&limit=`)
- `GET /api/contacts/export` — CSV (formula-injection sanitised)
- `GET|POST|PUT|DELETE /api/groups`
- `GET|POST|DELETE /api/templates`
- `POST /api/import` — multipart CSV (headers `Name|Nome`, `Phone|Telefone`, `Group|Grupo`)
- `POST /api/broadcast` — enqueue bulk send; 429 on concurrent + 10s cooldown
- `GET /api/broadcasts[/:id]` — history, drill-down
- `GET /api/stats`
- `GET /api/events` — SSE (connection state, broadcast progress, receipts)
- `GET /api/translations` — i18n bundle (ETag-cached)
- `POST /api/client-error` — frontend uncaught-exception sink
- `GET /api/outbox/dead` — dead-letter rows (exhausted retries)
- `GET /debug/vars` — expvar metrics (gated by `AUTH_TOKEN`)

## Conventions

- Handlers: `handle*` or area-specific verb (`listContacts`, `createGroup`).
- Translatable errors implement `LocalizedError`; surface via `handleError(w, r, status, err)` or `jsonErrorLocalized(w, r, status, key, args...)`. Raw `jsonError` only for non-translatable shapes.
- Logs via injected `*slog.Logger` on `App`/`SSEHub`/`Broadcaster`/`ContactStore` (no package-global). Use key-value pairs.
- SSE: `SSEHub.Broadcast` is non-blocking (drops on full channels, counted via `metricSSEDrops`). Every event payload is a typed struct in `sse_events.go`.
- Broadcast lifecycle: `Broadcaster.Start` returns a `*StartHandle` owning mutex/cancel/WG; exactly one of `handle.Done()` (success) or `handle.Abandon()` (validation fail post-Start) must run.
- Phone validation strict E.164: 7–15 digits, no leading `0`. Applied in API + CSV import.
- CSV import tolerant to PT/EN headers + Google Contacts + Outlook exports.
- Auth opt-in via `AUTH_TOKEN`. When set, all `/api/*` and `/debug/vars` require `Authorization: Bearer <token>` (or `?token=` for SSE).
- Every `ContactStore` method takes `context.Context` as first arg. Handlers pass `r.Context()`; broadcast goroutine uses its own ctx from `Broadcaster.Start`.

## Gotchas

- whatsmeow receipts (`wa_events.go:handleReceiptEvent`) mutate `broadcast_messages` under `WithTimeout(app.shutdownCtx, 2s)`. Keep status transitions consistent — don't duplicate writes in handlers.
- Frontend embedded at build time. After editing `internal/server/web/`, rebuild binary (`go build` / restart `go run .`). Docker image needs rebuild too. For prod bundle: `npm run build` then `go build -tags prod`.
- `store/` holds session secrets (mode 0700). Do not commit or ship. Deleting `device.db` logs the user out.
- cgo required (sqlite driver). Cross-compilation needs cgo toolchain; Dockerfile handles this.
- whatsmeow event loop runs in its own goroutines — any DB writes from event callbacks must use the `ContactStore` methods (they handle locking).
- Schema changes ship as new `.sql` files under `internal/server/migrations/`; never edit existing migration files in place — write a new one.
- Outbox retries: failed sends enqueue into `outbox`; `OutboxWorker` polls every 15s with exponential backoff (30s base, 5 attempts, ~15m total).
- Shutdown ordering: `runShutdown` cancels `shutdownCtx` → cancels broadcast → waits outbox WG → waits broadcaster WG → `server.Shutdown` → WA disconnect → DB close.
